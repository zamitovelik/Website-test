# Apogee — бэкенд

FastAPI + SQLite. Принимает заявки с сайта, сохраняет их в базу и отправляет
уведомление на почту. Плюс авторизация с настоящим хешированием паролей.

## Запуск

Из папки `backend`:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
uvicorn app.main:app --reload --port 8000
```

Интерактивная документация: http://localhost:8000/docs

Фронтенд в режиме разработки проксирует `/api` на этот порт (см. `vite.config.ts`),
поэтому больше ничего настраивать не нужно.

## Уведомления в Telegram

Самый быстрый способ получать заявки — бот в Telegram: не нужны ни пароли
приложений, ни двухэтапная проверка, ни SMTP.



Скрипт проверит токен, сам определит, куда слать сообщения, пришлёт
проверочное уведомление и сохранит настройки.

Токен бота выдаёт @BotFather: команда `/newbot`, затем имя бота и логин,
оканчивающийся на `bot`. В ответ придёт строка вида `1234567890:AAH…` — её
и нужно вставить в скрипт. Дальше он попросит написать боту любое сообщение,
чтобы узнать адрес получателя.

Почту и Telegram можно включить одновременно — тогда заявка придёт в оба
канала, и отказ одного не мешает другому.

## Настройка почты

Самый простой путь — один скрипт, который спросит данные, сам пропишет их
в `.env` и сразу отправит проверочное письмо:

```bash
python -m scripts.setup_mail
```

Он знает готовые настройки Gmail, Яндекс Почты, Mail.ru и Brevo — нужно только
выбрать пункт из списка и ввести логин с паролем приложения. Пароль вводится
скрыто и остаётся только в файле `.env` на вашем компьютере.

**Важно:** почтовые сервисы не принимают обычный пароль от аккаунта — нужен
отдельный «пароль приложения»:

| Сервис | Где взять |
|---|---|
| Gmail | https://myaccount.google.com/apppasswords (требуется включённая двухэтапная проверка) |
| Яндекс | Яндекс ID → Безопасность → Пароли приложений → Почта |
| Mail.ru | Настройки → Безопасность → Пароли для внешних приложений |
| Brevo | панель → SMTP & API → SMTP (двухэтапная проверка не нужна) |

Если Google пишет «Эта настройка недоступна для вашего аккаунта», значит не
включена двухэтапная проверка: https://myaccount.google.com/signinoptions/twosv

Проверить уже сохранённые настройки отдельно:

```bash
python -m scripts.send_test_email
```

Секрет для токенов генерируется так:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

**Пока почта не настроена, заявки всё равно сохраняются в базу** — не уходят
только письма, и в поле `email_error` у заявки будет причина.

## Пользователи

Вход открывает страницу  со списком заявок. Создать пользователя:

```bash
python -m scripts.create_user
```

Пароль вводится скрыто и хранится только как bcrypt-хеш.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/leads/demo` | Заявка на демо |
| POST | `/api/leads/contact` | Сообщение из формы контактов |
| POST | `/api/auth/login` | Вход, возвращает JWT |
| GET | `/api/auth/me` | Текущий пользователь (нужен `Authorization: Bearer …`) |
| GET | `/api/leads` | Список заявок (нужен вход) |
| GET | `/api/health` | Состояние сервиса и базы |

Заявки видно на странице `/leads` — нужно войти под пользователем,
созданным через `scripts/create_user.py`.

## Как это устроено

- **Заявка сохраняется до отправки письма.** Письмо уходит фоновой задачей, и
  если SMTP недоступен, заявка не теряется — ошибка записывается в `email_error`.
- **Reply-To** в письме указывает на адрес заявителя, поэтому «Ответить» в почте
  пишет сразу клиенту.
- **Ограничение частоты:** 5 заявок за 10 минут и 10 попыток входа за 5 минут с
  одного адреса. Счётчик живёт в памяти процесса — при нескольких воркерах
  понадобится Redis.
- **SQLite в режиме WAL**, чтобы чтение не блокировало запись.
- Ошибка входа одинакова для неверной почты и неверного пароля — чтобы перебором
  нельзя было узнать, какие адреса зарегистрированы.

## Развёртывание

SQLite хранит данные в файле, поэтому нужен хостинг с постоянным диском:
Railway, Render, Fly.io, любой VPS. На бессерверных платформах (включая
Vercel Functions) файл базы стирается между запусками — там нужна внешняя СУБД.

После развёртывания:

1. добавьте домен фронтенда в `CORS_ORIGINS`;
2. соберите фронтенд с `VITE_API_URL=https://адрес-бэкенда`.
